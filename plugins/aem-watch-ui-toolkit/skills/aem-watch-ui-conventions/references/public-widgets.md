# AEM 公共控件规则

只在选择、整理或扩展 `thirdparty/lib/aem` 公共控件时读取。

## 先验证再复用

- 新项目中先检查控件源码、头文件、构建入口和真实调用；旧项目存在 `aem_text`、`aem_arc_scrollbar` 或某个扩展接口，不代表当前分支也存在。
- 复用以交互和状态语义一致为主，外观相似只是辅助条件。部分相似时先指出缺少能力以及“扩展公共控件”和“保留页面特殊实现”的影响。
- 已有控件能满足时优先复用，不在业务页面重新拼装职责相同的实现。

## 默认实现与页面覆盖

- 页面调用公共控件前，先阅读当前分支创建函数，核对它已创建的子控件、默认图片和尺寸、事件、状态与对齐。默认实现已符合目标设计时，业务页面不再读取内部子控件或二次设置同一属性。
- getter、setter 和子控件访问只是已确认差异的扩展点，不是创建后的必做步骤。只覆盖确实不同的属性，保留公共控件已经正确的资源、点击行为和其他默认状态；无法证明差异时不覆盖。
- 覆盖默认图片前，同时核对替代资源的功能和状态语义、可见图形、正式输入像素与透明区，以及当前生效生成描述符的 `header.w`、`header.h` 和 `cf`；不根据文件名或 C 符号名推断可替换性。
- 页面修改完成后，搜索公共控件创建之后的 getter、子控件索引和图片、样式、事件二次设置；每个覆盖都必须对应已验证的页面差异，否则删除覆盖并使用公共默认。

## 抽象边界

- 单页独有的颜色、资源、状态、点击模型和布局留在页面内。
- 只缺少一个已确认且会重复使用的能力时，优先增加小型、语义明确的 setter/getter。
- 同一组合结构在多个真实页面稳定重复后再提取薄组合控件；“未来可能需要”不构成新增接口的依据。
- 未经用户或设计确认，不主动增加背景、边框、蒙版、动画、定时器、禁用态、variant、mode、配置结构、`_ex` 接口或兼容包装层。
- 公共控件变化会影响多个既有调用方时，先列出兼容性、状态模型和验证范围；不要把单页改造伪装成公共优化。

## 常见语义候选

以下名称只作为查找候选，使用前仍需在当前项目验证：

- `aem_bg`：纯色、无交互基础容器。
- `aem_page`：整屏页面或普通滚动根容器。
- `aem_zoom_list2`：项目使用统一基础尺寸、由容器计算视觉缩放的列表。
- `aem_title`：项目默认标题；具体布局、尺寸和扩展接口以当前分支实现为准。
- `aem_img_btn`：图片本身包含完整按钮外观且需要按压反馈的场景。
- `aem_switch`：两张正式图片表达开/关状态；业务点击通常由整行处理。
- `aem_checkbox`：单张选中图片通过显隐表达状态。
- `aem_single_zoom_btn`：普通背景、文本和整体按压缩小；不适用于高密度键盘的独立放大预览。

旧组合控件和业务化控件只在目标设计、状态和事件语义一致时保留，不作为新页面默认模板。

## 失败处理与格式

- 组件创建函数只把输入状态和必须返回的主要父控件视为失败出口；普通内部子控件失败时局部保护，除非缺少它会导致崩溃或核心功能不可用。
- 参数列表在合理行宽内保持单行；不要为套用风格批量格式化无关公共库代码。
- 公共控件测试和编译范围由当前项目规则决定；没有真实调用方和验证依据时，不宣称新接口已经通用。
