# 应用页面实施规则

只在实现、迁移或审查 `application/aem_watch` 应用页面时读取。

## 修改范围

先判断本次变化等级：

- 视觉变化：布局、尺寸、间距、颜色、字体、图片和文本表现。默认只做这一层。
- 行为变化：滚动、选择、显隐、交互状态、动态高度或数据刷新。必须有用户要求、现有代码、状态说明或已验证参考作为依据。
- 公共架构变化：公共控件接口、跨页面抽象、资源体系或数据接口。只有多个真实使用方已证明需要，或用户明确要求时实施。

不要因为 Figma 没有显示某段功能代码就删除它，也不要根据单张静态设计自行添加动画、定时器、状态或文本溢出行为。

## 实现前检查

1. 完整理解目标页面的创建、事件、刷新、生命周期和销毁路径。
2. 搜索当前项目已有图片符号、字符串 ID、公共控件和同类交互；能复用时不重复创建。
3. 查看与需求有关的全部设计状态，而不是只看一个画面。
4. 将可确认的视觉事实与行为推断分开；缺失信息只阻塞受影响部分，不妨碍继续处理已确认内容。
5. 参考旧分辨率页面时只复用功能和交互语义；最终坐标、尺寸、字号、图片边界和可视区域来自目标分辨率设计或同分辨率验证结果。

## 页面状态和数据结构

- 保持一个清晰的页面 UI 状态结构。需要刷新、显隐、选择或参与后续布局的关键控件保存指针，不依赖 `lv_obj_get_child(parent,index)` 获取关键对象。
- 同类型重复项目优先使用未指定长度的 `static const` 描述表，元素数量使用项目已有的 `ARRAY_SIZE(array)`；不要用多个平行数组表达同一项目，也不要为一次使用的数量再定义 `ITEM_COUNT`。
- 创建重复项目的函数优先接收项目描述指针，而不是接收下标后反复读取全局数组。
- 同一业务状态只保留一个权威来源；焦点、当前选择和已保存选择只有语义确实不同时才分别保存。

## 创建、刷新和生命周期

- `create_ui()` 创建控件并完成静态布局；`on_resume()` 或对应刷新入口从数据层更新动态状态。首次进入会依次调用两者时，纯状态刷新不要在两处重复执行。
- 刷新函数只更新它负责的状态。若 `refresh_item_ui()` 已负责图片、文本或选择态，创建阶段只设置首次必需的结构和静态样式，不再复制完整刷新逻辑。
- 刷新导致显隐、高度或顺序变化时，再执行必要的布局和列表缩放更新；纯图片或颜色变化不重建整页。
- 事件处理函数负责跳转或修改数据，布局代码留在创建或明确的布局辅助函数中。
- 子页面可能修改数据时，在恢复入口重新读取并刷新；保持原有首次进入、暂停、恢复和返回语义。

## 创建失败和释放

- 页面状态分配失败时直接返回；页面根对象、主列表或必要内容容器失败时清理页面状态后返回。
- 单个列表项、图标、文本或其他局部对象失败时，记录错误并跳过受影响对象；只要剩余页面仍可安全使用，就不得销毁已经创建的整页或直接造成黑屏。
- 连续列表中“上一项”指针只在当前项目成功创建后更新；后续项目相对于上一个成功、可见项目布局。
- 可选子控件创建后用局部判断保护配置。底层 API 已经处理某个空值时，不为同一位置再增加语义相同的多层回退。
- 当前 ATS308x SDK 家族的 `lv_obj_align_to(obj,NULL,...)` 会回退到父控件；迁移到不同 LVGL 版本时先检查实现，再决定是否沿用这一约定。
- 根页面释放其子树；独立定时器和不属于页面子树的资源在删除根页面前释放。停止入口调用页面统一的销毁函数，不展开第二套释放流程。

## 布局与尺寸

- 不使用一个全局缩放因子把旧分辨率布局当作新分辨率最终实现。多分辨率确实共存时，把差异集中在布局档案或少量选择入口；单目标页面不为已取消的旧分辨率保留无需求的条件分支。
- 能准确表达设计关系时，使用父子或兄弟相对对齐。固定尺寸控件不为了“看起来统一”改成无意义的动态计算。
- 父容器已通过 padding、位置或尺寸建立局部坐标系时，子控件直接使用相对该坐标系的最终偏移；不要在每次对齐时重复减去标题高度等全局值。
- 重复项目相对于上一个成功且可见的项目对齐，不用循环下标乘固定间距推导位置。
- 图片实际像素尺寸与目标设计一致时直接使用，不增加防御性缩放、裁剪或根据资源宽高反算坐标。状态图片共用布局前先确认尺寸一致；资源变化后重新验证。
- 动态文本或控件高度会影响后续布局时，后续控件相对它布局；固定位置且设计给出绝对坐标的对象不为了形式统一强改成相对布局。

## 宏和数字

- 宏或枚举常量用于有明确设计/业务语义、需要多处复用、统一调节、作为范围边界或参与条件编译的值。
- 单页只使用一次的固定坐标、尺寸、圆角、资源固有尺寸和零偏移通常保留在布局代码附近；宏若只让读者跳到文件顶部查看一个简单数字，就不应定义。
- 同一派生表达式在页面中重复出现并需要同步调整时，可以把计算结果定义为带括号的宏；表达式仍应体现屏幕或父容器尺寸、左右边距、文本安全区等来源。
- 宏名必须描述展开后的结果，而不是表达式中的某个操作数；例如计算结果是内容宽度时使用 `*_CONTENT_WIDTH`，不能把它命名为 `*_MARGIN`。
- 范围和单位换算被设置页、显示页等多个模块共用时，应提升到共同业务模块作为唯一来源。

## 文本

创建文本前先选择一种语义：

- Figma 文本节点的包围盒可能只是当前文案的实际边界，不能直接当作多语言文本容器宽度；设计表现为居中或对称留白时，容器宽度应由父宽或屏宽减去左右安全边距得到。
- 固定区域文本：标题、菜单项和固定单行区域使用设计给出的宽高；只有项目现有行为或设计明确要求时才启用循环滚动。
- 自适应正文：提示、说明、确认信息和多语言长文本允许换行，不启用跑马灯；高度使用可靠的内容高度或按实际字体、间距、宽度测量。

不得只设置换行文本宽度就假设高度安全。翻译文本的换行会影响容器或后续控件时，核对当前打包语言并保留内容自适应、文本测量或页面已有的等效布局关系；不要仅凭单一语言 Figma 的固定高度覆盖已有动态布局。已验证当前全部打包语言都能安全容纳的固定区域，仍可使用设计给定高度。检查较长语言文本不会覆盖后续控件、开关、图标或屏幕边缘。界面显示文本使用字符串资源，不直接写死中文或英文。

## 图片、状态和资源语义

- 选择图片时依次检查现有真实用法、功能和状态后缀、像素尺寸与透明区、最后才是文件名相似度。
- 正式图标存在时使用原始资源，不用截图、裁剪预览、近似绘制或 AI 重绘代替。
- Figma 简化样式不能作为复杂透明效果的唯一依据。节点存在透明填充、渐变或多重描边、内阴影、模糊、蒙版或混合模式时，继续核对原始 `fills`、`strokes` 和 `effects`；当前 LVGL 样式不能准确复现时导出原节点图片，不用单色背景或描边近似替代。
- 现有位图尺寸与目标设计不一致时，先检查 Figma 是否提供可直接导出的最终图片，并确认现有符号的资源归属和全部使用方；有目标尺寸原图且替换不影响无关页面时，更新其真实归属目录下的正式输入，不用代码缩放旧图代替。共享资源替换会影响其他页面、资源归属不明确或设计只提供局部效果时，先说明影响并确认是更新共享资源还是新增页面专用资源；只有没有可用原图或用户明确要求复用可缩放资源时才使用缩放，并复核透明边界和点击后的状态表现。
- 资源归属按已确认的实际消费者判断，不按 Figma 分区、菜单入口或首次使用页面判断。不含业务内容且尺寸、像素和效果完全一致的图片，在多个应用或模块真实复用时提升到项目公共资源目录，并按图标、按钮背景等语义类别建立子目录；类别目录已经表达语义时，文件名用尺寸或简短状态名区分即可。只有单一模块使用时留在模块公共目录，只有单页使用时留在页面目录。
- 视觉相似但尺寸、透明区、描边、阴影或状态含义不同的图片是独立变体，禁止为了减少文件数量而缩放或混用。同一公共图片只保留一份正式输入和一份资源声明；页面继续各自保存文字、事件和业务行为，除非控件结构也有多个真实使用方证明值得抽象。
- 未经设计或用户确认，不通过重着色、添加背景或组合控件模拟正式资源；只有资源明确是可着色蒙版时例外。
- 选中图片表达已保存或当前使用状态。滚动焦点不自动等于选择状态，除非现有交互明确如此。
- Figma 中可见但代码或产品配置中禁用的功能，必须同时确认需求、Activity/路由、构建入口和资源完整性后才能启用。

## 代码风格和复杂度

- 沿用目标文件已验证结构，只提取有明确职责或消除有意义重复的辅助函数。只调用一次、只配置一个样式的小函数通常直接内联。
- 函数声明、定义和调用在合理行宽内保持单行；明显过长时按语义分组，不机械地每个参数一行。
- 不为单页引入布局枚举、通用构建器、多层包装或公共接口，除非真实复杂度因此下降。
- 不格式化、重构或修改与当前需求无关的代码和构建文件。

## 验证

- 对本次手工修改文件执行 `git diff --check`，检查意外格式化、构建文件噪声和超出范围的变化。
- 静态检查页面边界、文本可视区、触摸区、列表滚动范围、空指针路径和资源释放。
- 编译、资源生成、模拟器和真机操作遵守项目规则与用户当前授权，不因页面修改自动扩大。
- 完成说明区分静态检查、编译、视觉和真机验证；未执行的部分不得描述为通过。
