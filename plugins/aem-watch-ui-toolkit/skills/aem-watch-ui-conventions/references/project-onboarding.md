# 新项目与规则迁移

在新项目、不同产品分支或新分辨率开始 UI 工作时读取。

## 目标

只迁移已经验证且能改变后续决策的规则。不要把旧工程的事实、待办和历史补丁整套复制到新项目。

## 调查顺序

1. 确认新项目 Git 根、可写目标、只读参考工程和现有 `AGENTS.md`。
2. 检查应用目录、板型、分辨率、资源输入/输出、UI Editor、翻译表、构建入口和当前打包语言。
3. 检查目标项目实际存在的 AEM/LVGL 控件、参考页面和 API 行为。
4. 将旧规则逐条分为个人习惯、UI 通用经验、资源流水线、项目事实和页面特例。
5. 只把新项目已经验证的事实写入项目规则；未验证项列为候选，不写成强制结论。

## 唯一归属

| 类型 | 存放位置 | 典型内容 |
|---|---|---|
| 个人习惯 | 用户全局 `AGENTS.md` | 编译授权、目标路径核对、规则维护方式、报告习惯 |
| UI 通用经验 | 本 Skill | 生命周期、刷新职责、失败处理、布局、宏、文本和控件抽象 |
| 资源流水线 | Figma/资源 Skill | Figma 读取、图片导出、翻译表、UI Editor、事务生成和 Post |
| 项目事实 | 仓库根或 `application/aem_watch/AGENTS.md` | board、resolution、路径、构建入口、资源策略、参考工程 |
| 模块/页面特例 | 最近的子级 `AGENTS.md` | 禁用功能、特定资源契约、模块独有参考页面 |

同一规则只保留一个权威版本。下级文件写差异和覆盖，不复制上级全文。

## 使用模板

`assets/project-rules/` 提供三个起点：

- `root-AGENTS.template.md`：工程路径、目标产品、权限和 Skill 路由。
- `aem-watch-AGENTS.template.md`：应用资源档案、单页交付和分辨率事实。
- `application-AGENTS.template.md`：当前分支控件能力、参考页面和局部覆盖。

复制后替换全部 `{{...}}` 占位符，删除不适用章节。模板不是完成的项目规则；没有实际检查过的路径、尺寸和工具不得保留。

## 维护规则

- 用户重复纠正的问题先检查是否已有通用条目；有则修正原条目和触发条件，不追加同义句。
- 一次性坐标、颜色、资源名和临时绕过不进入通用 Skill。
- API 行为只有在目标 SDK 源码或真实运行中确认后才记录，并注明迁移到其他版本时重新验证。
- 控制规则体积。入口只保留路由和关键边界，详细内容进入按需参考文件，避免一份超长 `AGENTS.md` 被截断。
- 换电脑时需要备份用户全局 `AGENTS.md` 和用户级 Skills；项目 `AGENTS.md` 是否跟随 Git 由用户决定。
