# 新分辨率接入

仅在 board/resolution 改变、Figma frame 与目标分辨率不一致，或目标分辨率资源档案
不存在时读取。普通同分辨率任务不执行本流程。

## 首次确认

1. 读取 [configuration.md](configuration.md)，通过项目覆盖 JSON 指定新的 board 和
   resolution；不要修改通用默认值来临时切换项目。
2. 运行一次 `ResourceEnvironment`，确认目标资源目录、UI 工程、Python 和生成输出；只有文本会变化时再运行 `TranslationEnvironment`。
3. 读取 Figma frame 的实际宽高并与目标分辨率比较。
4. 检查目标分辨率是否已有资源目录、`bt_watch.ui`、字体、公共控件和已验证页面。

## 参考文件策略

- 生命周期、事件、数据接口、资源释放和滚动语义属于行为参考，可以跨分辨率复用。
- 坐标、尺寸、字号、圆弧半径、图片尺寸和可视区域属于视觉参考，只能使用目标
  分辨率设计或同分辨率已验证页面。
- 不使用全局比例因子把旧界面直接缩放到新分辨率。
- Figma 与目标分辨率不一致且没有明确适配规则时，停止视觉实施并请求目标分辨率节点；
  不能自行发明设计。

## 后续复用

首次接入通过后，将稳定的 board、resolution 和路径保存为项目覆盖配置。同一批和后续
使用该配置的任务复用环境结果，只有工具、目录、board 或 resolution 再次变化时重新执行
本流程。页面专用坐标不写入通用 pipeline 配置。
